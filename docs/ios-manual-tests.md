# iOS 分享扩展：真机验收

模拟器单测覆盖文件字节、像素往返、中断后票据还在、以及 12MP 的内存计划。下面三步要在 Kin 的 iPhone 上做。Xcode 打开 `PrettyShotIOS` scheme，签名按 [ios-free-signing.md](ios-free-signing.md)。默认是 inline（没有 App Group）。

## 1. 12MP 分享不把扩展打崩（AC-I17）

1. 准备一张约 1200 万像素的图（长边大约 4000）。可以是相册里的 12MP 照片，或一张同级的长截图。不要用已经缩小过的预览图。
2. 系统分享 → PrettyShot。扩展应打开编辑，而不是闪退。
3. Xcode → Debug navigator → Memory：编辑过程停在大约 120MB 以下。界面可以出现「预览已降采样」。这一步不应该同时解开多份全尺寸位图。
4. 点「存入相册」或「复制」。12MP 按全尺寸走（PNG，不改成 JPEG）。若系统因为内存杀掉扩展，把这次的内存曲线记下来，不要当成通过。

模拟器代替不了 jetsam。单测只锁定「编辑时 0 份全尺寸解码、导出最多 2 份、3 份超过 120MB」。

## 2. 交给 App 的过程被打断，图还在

**inline（默认，免费 Apple ID）：**

1. 分享 2 张图，点「在 PrettyShot 中拼成长图」。
2. 应出现「还没交到 App」，并写明原图还在、当前签名不能交给 App。
3. 不要点取消。回到扩展（或这次分享还开着），图还能「按预览尺寸保存」。没有静默消失。

**App Group（按签名文档打开之后再测）：**

1. 分享 2 张图，点拼成长图，在系统尝试打开 PrettyShot 时上滑关掉扩展，或断掉这次打开。
2. 再打开 PrettyShot。首页应有「继续上次分享」，张数还在。
3. 点进去能看到这些图。看过之后那条暂存才消失。没点进去之前杀掉 App，再打开，暂存还在。

inline 的临时目录在扩展进程结束、或系统清 tmp 之后可能没了。跨进程还能找回，只承诺 App Group 那条。

## 3. 不静默压缩

1. 用一张 PNG 截图分享进扩展（相册或文件 App 都能看到原始宽高）。
2. 不点「按预览尺寸保存」。点「存入相册」。新照片的像素长边应不小于原图像素长边（美化会加边距，所以可以更大），格式不是 JPEG 重压出来的糊图。
3. 再分享一张明显超过 12MP 的图。不点预览保存时，不应直接存出一张小图。应先问：交给 App，或你自己点「按预览尺寸保存」。只有点了预览，toast 才是「已按预览尺寸保存」。
4. App Group 打开时，交给 App 的文件大小应和分享进来的原文件一致（同一张 PNG/JPEG，没有先缩小再存）。

## 单测已经覆盖的部分

| 检查 | 自动化 | 真机 |
| --- | --- | --- |
| 1. 12MP 不崩溃、inline 不留多份全尺寸解码 | 内存计划 + 2400×1600 合成图只拷文件、预览长边 ≤1280 | 第 1 步的 jetsam |
| 2. 中断后还能取出 / 明确失败 | 同一 inbox 里票据和像素都在，确认后才删除；源文件读不到时失败且不删原件 | 第 2 步 |
| 3. 不静默缩小、不有损重编码 | inline 交接后文件字节和像素与输入一致；12MP 走全尺寸 PNG，更大则先问，只有用户点了才预览 | 第 3 步的相册成片 |
