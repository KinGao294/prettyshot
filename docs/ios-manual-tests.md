# iOS 分享扩展：真机验收

模拟器单测覆盖文件字节、像素往返、中断后票据还在、以及 12MP 的内存计划。下面三步要在 Kin 的 iPhone 上做。Xcode 打开 `PrettyShotIOS` scheme，签名按 [ios-free-signing.md](ios-free-signing.md)。默认是 inline（没有 App Group）。

## 1. 12MP 分享不把扩展打崩（AC-I17）

1. 准备一张约 1200 万像素的图（长边大约 4000）。可以是相册里的 12MP 照片，或一张同级的长截图。不要用已经缩小过的预览图。
2. 系统分享 → PrettyShot。扩展应打开编辑，而不是闪退。
3. Xcode → Debug navigator → Memory：编辑过程停在大约 120MB 以下。界面可以出现「预览已降采样」。这一步不应该同时解开多份全尺寸位图。
4. 点「存入相册」或「复制」。12MP 按四份全尺寸缓冲估算超过约 120MB，所以扩展里不应直接导出。能交给 App 时出现「图片较大，去 App 里处理」和「在 App 中继续」；不能交给 App 时出现「改用 PrettyShot App 选图」。不要出现长边被截到 1280 的成片。普通手机截图（大约 300 万像素）仍应在扩展里按原分辨率存成 PNG。

模拟器代替不了 jetsam。单测只锁定「编辑时 0 份全尺寸解码、导出最多 2 份、3 份超过 120MB」。

## 2. 交给 App 的过程被打断，图还在

**inline（默认，免费 Apple ID）：**

1. 分享 2 张图。主按钮是「改用 PrettyShot App 选图」，文案写明原图没有被改动，请在 App 里重选。
2. 点这个按钮。PrettyShot 应打开相册选择器（原分辨率，不是缩小图）。相册里的原图还在，没有被改、没有被删。
3. 若系统没能打开 App，扩展停在同一页，可以再点一次。不要出现一张被缩小后存出的图。

**App Group（按签名文档打开之后再测）：**

1. 分享 2 张图，点「在 PrettyShot 中拼成长图」。先看到「正在交给 PrettyShot」，并写明原图还在。
2. 在系统尝试打开 PrettyShot 时上滑关掉扩展，或断掉这次打开。应落到「改用 PrettyShot App 选图」，并可以「再试一次」。
3. 再打开 PrettyShot。首页应有「继续上次分享」横幅，张数还在。
4. 点进去能看到这些图，像素是原文件的。看过之后那条暂存才消失。没点进去之前杀掉 App，再打开，暂存还在。

inline 的临时目录在扩展进程结束、或系统清 tmp 之后可能没了。跨进程还能找回，只承诺 App Group 那条。相册里的原图两条路都不动。

## 3. 不静默压缩

1. 用一张 PNG 截图分享进扩展（相册或文件 App 都能看到原始宽高）。
2. 点「存入相册」。新照片的像素长边应不小于原图像素长边（美化会加边距，所以可以更大），格式是 PNG，不是 JPEG 重压出来的糊图。界面上没有「按预览尺寸保存」。
3. 再分享一张明显超过 12MP、两份全尺寸位图会超过约 120MB 的图。扩展不应直接存出一张小图。能交给 App 时先出现「图片较大，去 App 里处理」和「在 App 中继续」；不能交给 App 时出现「改用 PrettyShot App 选图」。两条路都不写出降采样的导出文件。
4. App 里从相册选图再「开始拼接」，拼接用的是原图像素，不是长边 1600 的缩图。
5. App Group 打开时，交给 App 的文件大小应和分享进来的原文件一致（同一张 PNG/JPEG，没有先缩小再存）。

## 4. 免费个人团队：扩展能否把原图交给 App（M3，CI 不能代劳）

1. 用免费 Apple ID 的 Personal Team 签名安装 PrettyShotIOS 和分享扩展。保持仓库默认的 inline，先不要开 App Groups。
2. 分享一张图，确认扩展里 `canTransferToApp` 的表现是：超预算时主按钮为「改用 PrettyShot App 选图」，App 不会自己出现「继续上次分享」。
3. 按 [ios-free-signing.md](ios-free-signing.md) 打开 App Groups，重新安装。看两个 target 的 `containerURL(forSecurityApplicationGroupIdentifier:)` 是否非 nil。
4. 再分享 2 张图，点拼成长图。若首页出现「继续上次分享」且点进去的像素与原图一致，记为「免费个人团队可以交接原图」。若 Xcode 拒绝 App Groups，或容器是 nil，记为「不行」，兜底保持「改用 PrettyShot App 选图」。
5. 把结果写回 PR。这一步在模拟器 CI 里没有 Personal Team，不能当成已经通过。

## 单测已经覆盖的部分

| 检查 | 自动化 | 真机 |
| --- | --- | --- |
| 1. 12MP 不崩溃、导出峰值按四份缓冲算 | 真实渲染（打码 + 阴影）的源图、打码图、画布、阴影层字节；12MP 四份超过 120MB，改走交接或 S10f，不缩小导出 | 第 1 步的 jetsam |
| 2. 中断后还能取出 / 明确失败 | 同一 inbox 里票据和像素都在，确认后才删除；源文件读不到时失败且不删原件 | 第 2 步 |
| 3. 不静默缩小、不有损重编码 | inline 交接后文件字节和像素与输入一致；超过预算且不能交接时是「回 App 重选」，不是缩小导出；拼接输入和 App 导出保持源像素尺寸（美化只加边距） | 第 3 步的相册成片 |
| 4. 免费个人团队能否把原图交给 App | 默认 inline 的 `canTransferToApp == false`；CI 无 Personal Team | 第 4 步 |
